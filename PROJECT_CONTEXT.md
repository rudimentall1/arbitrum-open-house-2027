# Project context

## Purpose

Working repository for preparation, research, and implementation for Arbitrum Open House São Paulo 2027 / Buildathon.

The project is currently a clean scaffold. No product direction, winning concept, customer demand, partnership, or technical integration is treated as confirmed.

## Repository structure

- `AGENTS.md` — mandatory engineering and documentation rules.
- `PROJECT_CONTEXT.md` — project purpose, architecture, and verified context.
- `TASKS.md` — prioritized work queue and completion status.
- `DECISIONS.md` — durable decisions with rationale and evidence.
- `src/` — application and research-support code.
- `tests/` — automated tests.

## Technical baseline

- Runtime: Node.js (ES modules).
- Dependencies: none at scaffold creation.
- Tests: Node.js built-in test runner (`node --test`).
- Main entry point: `src/index.js`.

## Evidence discipline

Distinguish:
- **Verified** — directly checked against a source, test, repository, or working integration.
- **Unverified** — plausible but not yet confirmed.
- **Rejected** — tested or researched and found unsuitable, with the reason recorded.

Do not describe a prototype, mock, authorization decision, or simulated transaction as a completed external execution.
